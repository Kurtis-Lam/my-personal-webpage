Kurt

A CLI app that aggregates free open-source models from Hugging Face to work for you. Type kurt in any project folder, chat in plain English, and it can read your code and propose edits, new files and shell commands.

Step-by-step setup Source on GitHub

What is it?

Kurt is a terminal coding assistant powered by Qwythos, running locally through Ollama. Nothing changes until you confirm it.

  • 100% local: your code never leaves your computer.
  • Works on macOS (Intel and Apple Silicon) and Windows.
  • Tunes itself: it detects your hardware and picks the fastest safe settings.
  • Safe edits: a colored diff before every edit, with /undo to revert.
  • Any model: add other models from Hugging Face, a link, or an Ollama name.

Setup: step by step

You only do this once.

  1. 1

    Install Ollama and download the model

    Install Ollama, then run this once in a terminal:

    ollama run hf.co/empero-ai/Qwythos-9B-Claude-Mythos-5-1M-GGUF:Q4_K_M

    When you see the >>> prompt, type /bye to exit. The model is now downloaded. If you skip this step, Kurt offers to download it the first time you run it.

  2. 2

    Download Kurt from GitHub

    1. Open the repository page on GitHub.
    2. Click the green Code button, then Download ZIP.
    3. Unzip it. You get a folder such as kurt-main. Remember where it is.
  3. 3

    Install

    Open Terminal and run:

    cd ~/Downloads/kurt-main
bash install.sh

    Open the unzipped folder and double-click install.bat, or run it from PowerShell:

    .\install.bat

    The installer creates a private Python environment in ~/.kurt (Windows: %USERPROFILE%\.kurt) and adds the kurt command to your PATH. It does not touch your system Python.

  4. 4

    Open a new terminal window

    The PATH change only applies to terminals opened after installing. Check it worked:

    kurt --version

Using Kurt

Go to any project folder and start it.

cd ~/projects/my-app
kurt

On start, Kurt will:

  1. Start Ollama if it is not running.
  2. Load Qwythos into memory (the first load can take a little while).
  3. Show a green K mascot and a bottom-pinned kurt input box.

Now just talk to it. The input box stays pinned to the bottom of the terminal with /help, /models and @file hints inside. While Kurt works, thinking text and responses appear above it. Press Esc (or Ctrl+C) to stop generation.

Examples:

kurt ❯ add input validation to the signup function in @auth.py
kurt ❯ write a unit test for utils/dates.py
kurt ❯ why does main.js throw "undefined is not a function"?

How edits are confirmed

When Kurt wants to change something, you see a diff and a question:

╭──────────────╮
│ Edit auth.py │
╰──────────────╯
- def signup(email):
+ def signup(email: str):
+     if "@" not in email:
+         raise ValueError("invalid email")
Apply this edit? (y=yes, n=no, a=yes to all) [y/n/a] (y):
  • y applies this change.
  • n rejects it. Kurt is told, and you can explain what you want instead.
  • a applies this and all further file edits this session.
  • Shell commands (RUN) always ask, defaulting to no, even in auto mode.

Kurt can only read and write inside the folder you launched it from.

Commands

CommandWhat it does
/helpShow help
/speedShow the detected hardware and the speed settings in use (/speed refresh re-detects)
/think [on|off|auto]Turn thinking on or off. Off is much faster on computers without a GPU
/fast [model]Switch to a small, much faster model (default qwen2.5-coder:3b, about 2 GB)
/filesList the project's files
/add <path>Load a file into the conversation (or write @path inside any message)
/autoToggle auto-accept for file edits
/undoRevert the last applied change (can be repeated)
/clearForget the conversation and start fresh
/exitQuit (Ctrl+D also works)

Tips for good results with a 9B model

  • Be specific and point at files, for example fix the bug in @src/api.py line ~40.
  • Ask for one change at a time. Small models do much better on focused tasks.
  • If an edit fails to match, Kurt re-reads the file and retries. If it keeps failing, say rewrite the whole file and it uses a full-file write.
  • Use /clear when switching tasks so the context does not fill up.
  • Commit to git before big changes, as a second safety net next to /undo.

Speed

Kurt checks your computer the first time it runs (cached in ~/.kurt/hardware.json) and prints one line at startup, such as Intel Mac · CPU only, 6 cores, 16 GB RAM → ctx 8192 · 6 threads · thinking off.

Your computerWhat Kurt does
Intel Mac (no GPU support in Ollama)CPU inference with one thread per physical core, a shorter context (4096-8192 depending on RAM), thinking off
Apple Silicon MacMetal GPU, context sized to your unified memory, larger prompt batches on 16 GB or more, thinking on, Flash Attention
Windows with an NVIDIA GPUContext sized to your VRAM so the model never spills onto the CPU, larger batches on 8 GB or more, thinking on, Flash Attention
Windows without a supported GPUSame as an Intel Mac: CPU threads, short context, thinking off

Type /speed to see what was detected and applied.

Configuration (optional)

Set these environment variables before running kurt.

VariableDefaultMeaning
KURT_MODELthe Qwythos model aboveAny other Ollama model name
KURT_CTXauto (4096-16384)Context window in tokens (bigger = more memory use)
KURT_THREADSautoCPU threads used for inference
KURT_BATCHautoPrompt batch size
KURT_THINKautoon or off: whether the model thinks before answering
KURT_TUNEonoff disables all hardware auto-tuning
OLLAMA_HOSThttp://127.0.0.1:11434Use a remote or custom Ollama server

Examples:

# macOS
KURT_CTX=32768 kurt
# Windows PowerShell
$env:KURT_CTX = "32768"; kurt

Adding models (any format)

Type /models then + and give it a Hugging Face repo, a link, an Ollama name (llama3.2:3b), or search words. Ollama only runs GGUF, so for other formats Kurt works through these steps automatically.

  1. 1

    GGUF repo

    Pulled directly. Use user/name:Q4_K_M to pick a quantization.

  2. 2

    Not GGUF (safetensors, FP8, ...)

    Kurt looks for a ready-made GGUF conversion and offers it.

  3. 3

    No conversion available

    Kurt downloads the original weights (resumable) and imports them with ollama create, quantizing to Q4_K_M by default.

    • Pre-quantized repos (FP8 / AWQ / GPTQ) cannot be imported by Ollama directly. Kurt offers the full-precision original instead, or converts them if llama.cpp is available (export KURT_LLAMA_CPP=~/llama.cpp, needs pip install torch transformers gguf).
    • Gated repos: accept the terms on huggingface.co and set HF_TOKEN.

Troubleshooting

kurt: command not found / 'kurt' is not recognized

Open a brand-new terminal window. On macOS you can also run source ~/.zshrc. If it still fails, re-run the installer.

Ollama isn't installed or isn't on PATH

Install Ollama from ollama.com/download, then open a new terminal.

Windows: "Python not found"

Install Python from python.org and tick Add python.exe to PATH. If Windows opens the Microsoft Store instead, turn off the python.exe app execution alias in Settings → Apps → Advanced app settings → App execution aliases.

It's slow or the Mac gets hot

A 9B model is heavy. Close other big apps and run /speed to see the settings Kurt picked. You can lower KURT_CTX further (for example 4096) or pick a smaller model with /models. Intel Macs have no GPU acceleration for Ollama, so expect slower responses than on Apple Silicon.

Edits don't apply ("SEARCH not found")

The model sometimes misquotes your code. It retries automatically, so keep requests small and mention the file with @file.

Safety notes

Kurt is a small local model and can be wrong. Read every diff before pressing y, and read every shell command before running it. Do not use a (accept all) on code you cannot easily restore.

Updating and uninstalling

Updating

Download the new ZIP from GitHub, unzip it, and run the installer again (bash install.sh or double-click install.bat).

Uninstalling

macOS: bash uninstall.sh. Windows: double-click uninstall.bat. This removes Kurt only. Remove the model with:

ollama rm hf.co/empero-ai/Qwythos-9B-Claude-Mythos-5-1M-GGUF:Q4_K_M
